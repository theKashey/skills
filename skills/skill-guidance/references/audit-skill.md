# Audit a skill

Determine whether an existing skill predictably changes the right agent choices
at justified recurring cost. Review only; do not edit unless the user expands
the mutation scope.

## Completion contract

Finish when every runtime route and retained obligation in scope has an
evidence-backed verdict, findings identify exact locations and minimal repair
directions, and unobserved runtime behavior remains explicitly unvalidated.

## 1. Establish the audit boundary

State whether the audit covers the whole skill or a change set. Name the
intended activations, reader, mutation boundary, target harness behavior, and
available behavioral evidence.

## 2. Trace the decision map

For each route, infer:

- activating task and invocation mechanism;
- choice the route changes and default it must beat;
- authority and canonical owner;
- procedure, branch-specific inputs, and stopping condition;
- deterministic enforcement already covering the rule;
- runtime and human discovery cost.

Flag a route whose intended behavior requires producer explanation rather than
being inferable from the package.

## 3. Apply the laws

Apply every decision law and admission requirement in the parent `SKILL.md`;
do not redefine them here. Cite the canonical law for each failure. Also check
description-to-route coverage, direct and conditional reference pointers,
present-state wording, clean end-state, and route-specific completion
criteria.

## 4. Report evidence, not taste

Order findings by observed frequency and consequence. For each finding report:

- severity and exact artifact location;
- affected activation and plausible wrong behavior;
- broken law or contract;
- evidence and authority;
- smallest repair direction;
- validation that would prove the repair.

Separate `BLOCK` from `NEEDS-HUMAN-DECISION` and `UNVALIDATED`. Do not declare
runtime success from clean prose, structural validity, tool use, or instruction
compliance alone.
